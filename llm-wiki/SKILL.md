# llm-wiki — 知识库体系与文档站工具链

把散乱的项目文档变成**可导航、可检索、可保鲜、可交付**的知识库。

> **一句话原则**：判据来自本 skill；目录名、命令、落点**来自项目声明段**（模板见 `TEMPLATE.md`）。

## 定位与边界

- **管知识资产的「空间轴」**：东西放哪个格子、怎么保鲜、怎么对账、怎么交付。
- **不管「时间轴」**：何时做哪一步归 `agent-pipeline`；执行期看板归 `plan-persist`。
- **理论源头**：Andrej Karpathy 的 **LLM Wiki pattern**——与其在每次查询时从原始文档现场检索（RAG），不如让 LLM **增量维护一个持久 wiki**：「编译一次、持续保鲜」，交叉引用已建好、矛盾已标记。
- **零项目路径假设**：本 skill 不出现任何具体项目的路径／命令。项目通过 `AGENTS.md` 的 `## 知识库` 声明段提供取值。
- **最小默认**（项目未声明时）：知识库根 `docs/`、源层 `docs/raw/`、出口层 `docs/dist/`；无台账；门禁命令为空。

## §1 三层模型（谁拥有哪一层）

| 层 | 内容 | 谁拥有 | 关键约束 |
|---|---|---|---|
| **源** | 原始素材：调研记录、截图、导出数据、外部仓快照 | 人（策展） | **不可变**——LLM 只读不改 |
| **编译** | 整理后的结论：设计稿、参考、分析、索引 | **LLM 维护** | 可重建；每篇自带变更记录 |
| **出口** | 对外成品：PDF、交付包、汇报材料 | 人（签发） | **唯一对外面**；脱敏与口径在此一处把关 |

- **schema 层**（第 0 层）：`AGENTS.md` 与其声明段——人与 LLM 共同演进，决定前两层长什么样。
- **源 → 编译**是「提炼」，**编译 → 出口**是「材料化」；**跨层不得直连**（源不直转出口）。

## §2 目录四理念（P1–P4）

> 目的：让**人眼可导航**，而不是只能靠搜索。每条都有**机械判据**（可被 `llmwiki lint` 检查）。

| 编号 | 理念 | 判据 |
|---|---|---|
| **P1** | **目录预算**：任一目录的**直接子项 ≤ 24**（一屏可浏览） | 超限即报，必须分组 |
| **P2** | **增长轴被有界轴包夹**：路径 = 稳定轴 → 有界轴 → 增长轴 | 任何**取值无上限**的路径段，其左侧必须有有界分组 |
| **P3** | **分组轴真实且语义化**：禁止臆造分组（如 `1-50/`） | 分组名须来自项目事实（阶段／主题），可被一句话解释 |
| **P4** | **结构即导航**：目录层级 = 站点导航层级 | 导航由目录自描述文件生成，**不维护手工 nav 清单** |

- **反面教材**（P2）：`plans/<域>/MT-147.md`——增长轴（编号）在最右且无界，稳定轴（域）在浅层却承担全部增长，目录必然膨胀。
- **正面**（P2）：`plans/<域>/300-engineering/MT-147.md`。
- **P4 是使能技术**：没有它，P1–P3 的落地成本高到没人愿意重组目录。手段见 §6 的 `nav build`。

## §3 落库分流（五类真源，禁重复记）

**信息差＝协作事故**。凡影响后续协作的内容，必须落到**唯一对应**的一格：

| 性质 | 落点 | 判据 |
|---|---|---|
| **决策**（含否决理由与影响面） | 决策台账 | append-only；编号全局递增**永不复用**；口径变更**不改旧条**，新增条目并注明「修订 D-xxx」 |
| **范围与切片** | 计划目录 ＋ 计划索引 | 非简单任务先计划再执行 |
| **机制与口径** | 设计稿目录 | 成熟后搬正式站 |
| **时间线** | 时间线索引 | **一行式**（何时·谁·做了什么·落在哪）；叙述细节归计划 |
| **环境事实／操作步骤** | 对应域 `AGENTS.md` | 敏感值只走不入仓的 `.env*` |

**冲突消解**：口径冲突以台账中**最新日期／序号**为准。修订只能新增条目——历史永不回改（除非改名导致链接失效，见下）。

## §4 三操作

| 操作 | 做什么 | 何时做 |
|---|---|---|
| **ingest** | 新素材入源层 → 提炼进编译层 → 更新索引 ＋ 追加时间线一行 | 每次有新素材 |
| **query** | 对编译层提问 → 综合回答；**回答中可复用的部分回填成新页面** | 随时 |
| **lint** | 体检：断链／孤儿页／目录超预算／过时断言／跨页矛盾 | 收尾、定期 |

**query 回填**是这套体系与「对话即弃」的根本差别：想明白了的东西要**落成页面**，否则等于没想。

## §5 多写者治理（多 agent 并发）

- **上锁文件**：决策台账／计划索引／时间线／站点配置——提交前**逐文件核对**，只带自己的行。
- **提交纪律**：`git commit --only <精确 pathspec>`；禁裸 `git commit`、禁裸 `git add -A`；回退前先 `git log` 核对。
- **开工前必读**：决策台账 ＋ 计划索引。
- **历史不回改**：例外是「改名导致链接失效」——此时全量替换（含历史），并在台账留一条说明。

## §6 CLI（`cli/llmwiki`）

本体 **stdlib-only**；构建类子命令**调用**外部工具（`mkdocs` / `mmdc`），不内嵌。

| 命令 | 作用 | 依赖 |
|---|---|---|
| `llmwiki check-deps` | 校验 mkdocs 及插件（含主版本硬上限） | — |
| `llmwiki build [--strict]` | 构建站点（strict＝警告即失败） | mkdocs |
| `llmwiki serve start/stop/status [--full]` | 本地预览（默认增量） | mkdocs |
| `llmwiki nav build` | **由目录生成导航**（`.pages`），落实 P4 | — |
| `llmwiki lint [--semantic]` | P1 目录预算／断链／孤儿页；`--semantic` 加过时断言与跨页矛盾 | — |
| `llmwiki drift` | 上游仓（如被调研代码）演进 vs 我方分析篇的**时差** | git |
| `llmwiki export --llms-txt` | 生成 AI 可消费出口 | — |
| `llmwiki pdf <src> <out> <stem>` | mermaid 转 PNG 中转（供 md→pdf） | mmdc |

**配置**：项目根 `.llm-wiki.toml`（端口、目录映射、模板）。无配置时用最小默认。

## §7 项目声明段（`AGENTS.md`）

```markdown
## 知识库

- 知识库根：`docs/`
- 源层：`docs/raw/`
- 出口层：`docs/dist/`
- 决策台账：`docs/raw/decisions.md`（`D-NNN`）
- 计划落点：`.agents/plans/` ＋ 索引 `index.md`
- 设计稿：`docs/raw/design/`
- 时间线：`docs/raw/agent-task-log.md`
- 门禁：`tz docs --strict build`
- 上锁文件：`decisions.md`／`plans/index.md`／`agent-task-log.md`／`mkdocs.yml`
```

## §8 落地检查清单

1. 三层齐备（源／编译／出口）且**跨层不直连**
2. 每个目录直接子项 ≤ 24（`llmwiki lint` 全绿）
3. 五类落库**各有单一落点**，无重复记录
4. 导航由目录生成（无手工 nav 清单）
5. 时间线**一行式**，细节在计划／设计稿
