# AGENT.md — agent-pipeline

`SKILL.md` 是流水线正文；本文件是**运行指引**：怎么装、怎么接到一个项目、怎么覆盖默认、怎么维护。

## 安装

```bash
# 通用 / Codex
mkdir -p ~/.agents/skills && cp -r agent-pipeline ~/.agents/skills/
# Claude Code
ln -s ../../.agents/skills/agent-pipeline ~/.claude/skills/agent-pipeline
# pi
ln -s ../../../.agents/skills/agent-pipeline ~/.pi/agent/skills/agent-pipeline
```

装完用 `agent-doctor` 自检软链与发现是否生效（`bash ~/.agents/skills/agent-doctor/scripts/doctor.sh`）。

## 首次接入一个项目

1. **读 `TEMPLATE.md`**，把声明段复制进项目根 `AGENTS.md`。
2. **逐项填值**：按 `TEMPLATE.md` 的**全部 15 个字段**填（漏填任一项＝声明残缺）。
3. **跑自检三条**（模板末尾）：路径存在或可创建、门禁命令真跑得通、红线是「永不」。
4. **试一次接入判定**：让 agent 执行 `SKILL.md` §0，看它给出的位置报告是否符合你对项目现状的认知。若不符，多半是**痕迹位**没建立（见下）。

## 痕迹位：流水线能接入的前提

七环靠**痕迹位**被探针发现。若项目的计划模板里没有这些位置，接入判定会永远退到"更早的环"。建议项目在自己的计划模板里保留：

| 环 | 项目侧要有的位置 |
|---|---|
| 1 | 计划有「缘起／需求理解」节 |
| 2 | 计划索引有登记行；`Context` 段有事实取证（`file:line`／命令／一手链接） |
| 3 | 计划头可写 `> 审阅: <日期> <结论>` |
| 4 | 进度表（每行一模块，含状态列） |
| 5/6 | 「执行记录」段（追加式） |
| 7 | 计划头状态字段 ＋ 索引状态列 |

> 只需这些"位置"存在，**格式由项目自定**——skill 只认位置，不认格式。
>
> **位置没建起来也不会崩**：探针会退回“计划正文中有对应记录”（如「执行记录」里写过一行审阅结论）——但判定可靠性显著下降，且容易退到更早的环。所以**建位置**比**改判据**划算。

## 触发方式

**默认自动**：agent 遇任务先按 `SKILL.md` §1 分诊，**L1 及以上自动进入对应环**——不必等用户点名。显式指定用于**覆盖起点或力度**。

| 场景 | 怎么起 |
|---|---|
| 自动（默认） | 直接说任务——agent 自行分诊并走对应环 |
| 指定起点／力度 | 「按 agent-pipeline 执行 <任务>」「只走执行环」「这是 L3」 |
| 中途接入 | 直接说「接入流水线」或「继续 <计划>」，agent 先做 §0 位置判定 |
| 托管 | 说「托管跑／无人值守」；或建 `.agent/pipeline/autonomy`；或声明段写 `托管默认: 开` |

## 覆盖与扩展

- **加严而不放松**：项目可以收紧阈值（例："任何改库表结构都必须走第 1 环"），**不建议**放松（放松等于放弃流水线的价值）。
- **加环**：在项目声明里写明"本项目额外要求 <X>"，由项目自己的 `AGENTS.md` 承载——**不要改本 skill**。
- **改判据**：若发现某环的判据在本项目系统性误判，先改**痕迹位**（多数误判源于痕迹位缺失），再考虑改判据。

## 常见问题

| 症状 | 原因 ／ 处置 |
|---|---|
| 总是判定为「第 1 环」 | 计划缺「缘起」节或索引没登记 → 补痕迹位 |
| 判定矛盾（进度表绿但无提交） | 按 §0 规则 2 退到能确证的最早环，重跑该环 |
| `handoff` 无法自动调用（带 `disable-model-invocation`） | **属预期**：降级为 `/new` ＋ 在计划「执行记录」写明「应交未交：<交接内容摘要>」（`SKILL.md` §4）；不要因此阻塞流水线 |
| `handoff` / `new` 命令在当前 agent 不存在 | 按**能力**找等价物（§附映射表末尾说明）；都没有时至少 `/compact` |
| 质量轮跑不动 | 检查 sub-agent 能力是否启用；不可用则内联并**声明**这是单遍内联审阅 |
| 托管时卡住不动 | 查 `## 托管阻塞点`——②档阻塞是设计行为，不是故障 |

## 与 plan-persist 的分工

- **`plan-persist`**：执行期的**载体**——`.agent/plans/` 落盘、五态机、进度表驱动中断续作。
- **`agent-pipeline`**：**编排与闸门**——七环顺序、接入判定、外层循环（多计划）、上下文卫生、托管。

一句话：`plan-persist` 回答「这个计划做到哪了」；`agent-pipeline` 回答「整件事走到哪一步了、下一步该谁」。
