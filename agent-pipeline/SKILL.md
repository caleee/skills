# agent-pipeline — 跨 agent 工作流水线

把「追问 → 计划 → 审阅 → 执行 → 简化 → 审查 → 收尾」编排成一条**可中断、可接入、可托管**的工作流水线。

> **一句话原则**：**判据来自本 skill，命令与落点来自项目声明。**

## 定位与边界

- **是编排器，不是能力本体**：第 1／2／5／6 环点名既有 skill（`grilling`／`plan-persist`／`research`／`simplify-code`／`code-review`），收尾的提交信息另点名 `commit-message`；本 skill **不复制**它们的正文——复制即漂移。
- **零项目路径假设**：本 skill 不出现任何具体项目的路径、命令、台账名。项目通过 `## 工作流水线` 声明段提供（模板见 `TEMPLATE.md`）。
- **最小默认**（项目无声明时）：计划落 `.agent/plans/`（由 `plan-persist` 建）＋ 无外部台账 ＋ 门禁命令为空（跳过所有需命令的判据）。
- **不越权**：推送、发布、破坏性操作**不属于流水线收尾**（见 §6）。

## §0 接入：先判位置，再续跑

任何时候都可接入——新会话、接手别家 agent 做的计划、执行中断、上下文被清理。**不要从头重跑。**

### 位置探针表（＝各环的痕迹位）

> 本 skill 不硬编码任何路径：证据**优先取声明指定的位置**；括号内是**推荐约定**，项目未采用时退回「计划正文中有对应记录」。

| 环 | 完成证据（痕迹位） |
|---|---|
| 1 追问对齐 | 计划中有需求／缘起记录（推荐计划头 `> 已裁决: <日期>`），**或**声明指定的决策台账已有对应条目 |
| 2 计划落盘 | 计划文件存在 **且** 计划索引有该行 **且** `Context` 段含事实取证（`file:line`／命令／一手链接） |
| 3 审阅计划 | 计划中有审阅结论记录（推荐计划头 `> 审阅: <日期> <结论>`） |
| 4 执行 | 进度表存在 ☑ 行（**有对应提交是增强证据，不作必要条件**） |
| 5 简化轮 | 计划「执行记录」有简化轮记行 |
| 6 审查轮 | 计划「执行记录」有审查轮记行，**或**声明指定的报告落点存在报告 |
| 7 收尾 | 计划状态＝已完成 **且** 索引状态同步 **且** 声明指定的时间线已记行（若有） |

### 判定规则

1. **从后往前探**：最先"未完成"的环即**当前环**。
2. **不确定就退**：证据不足或互相矛盾 → 退到**能确证的最早一环**（安全侧：宁可重跑一遍审阅，也不漏掉一环）。
3. **输出位置报告**（一句话），再开工：
   `位置：第 3 环 审阅计划（依据：计划已落盘且索引有行，但计划中无审阅结论）`
4. **各环可重入**：已完成的动作不重做；半完成则只补缺的部分。
5. **不重问已定事项**：计划已记录的决策直接沿用；与台账冲突时**以台账最新序号／日期为准**，并新增条目注明「修订 <编号>」，**不改旧条**。
6. **不停下等确认**：判定后直接续跑（托管模式同样如此）；只有落入 §5 的②／③档才停下。

## §1 分诊：力度随任务

| 级 | 判据 | 走哪几环 |
|---|---|---|
| L0 | 单行问答、只读查询 | 不走流水线 |
| L1 | <4 步且无需计划（**跨文件本身不升级**） | 4 执行 → 7 收尾 |
| **L2（默认）** | 非平凡：**≥4 步**（含跨模块协调） | 2 计划 → 3 审阅 → 4 执行 → 7 收尾 |
| L3 | 口径未定、高不确定、影响面大 | 从 1 追问对齐 起走满七环 |

- **不确定时取更高级别**；级别可在过程中**升级**（执行中发现口径问题 → 回到第 1 环）。
- **非平凡任务的默认路径不含 5／6 环**；质量轮按需追加（用户要求、或改动面大时；声明段 `质量轮触发: 必须` 时必走）。
- **本表决定编排环序，不决定是否落盘**：`plan-persist` 有自己的建盘阈值（≥3 步），它可能在 L1 任务中落盘；该计划**不参与**本流水线环序（不作为第 2 环痕迹位）。两阈值**刻意不同源**——落盘成本低、编排成本高。
- **L1 无计划**时，§6 收尾的第 1／2 项（计划状态回填／托管记录回填）跳过。
- 阈值可由项目声明收紧（例：任何改库表结构都必须走第 1 环）。

## §2 七环

每环六元组：**目的｜进入证据｜动作｜退出判据｜痕迹位｜可重入**。其中**进入证据 ＝ 痕迹位**（同 §0 探针表，已完成则跳过），不再重复列出。

### 第 1 环 · 追问对齐

- **目的**：把未定的口径问到「共享理解」，而非边做边猜。
- **进入证据**：同 §0 第 1 环。
- **动作**：委派 `grilling`（Claude Code 侧 `/grill-me`）。一次一问、带推荐、**先自己调研**（**决策所需事实**；计划所需事实见第 2 环）。
- **退出判据**：每轮共识确认完成；**裁决落到声明指定的决策台账**（append-only，编号全局递增永不复用）。
- **痕迹位**：同 §0 第 1 环。
- **可重入**：新增未决项时回到本环，**只问新的 frontier**，不重开已决项。

### 第 2 环 · 计划落盘

- **目的**：先取证、再落盘；以进度表为唯一可信源。
- **进入证据**：同 §0 第 2 环。
- **动作**（两步，顺序不可换）：
  1. **调研取证**——委派 `research`（一手来源；可委派后台 agent），产物写入计划 `Context` 段（或独立调研文档）；**第 1 环已取证的直接复用**。
  2. **落盘计划**——委派 `plan-persist`（**5 段骨架 ＋ 末尾验证段**）。
- **退出判据**：计划含骨架与**可判定的验收**；索引已登记；**`Context` 段含事实取证**（`file:line`／命令／一手链接）——全凭印象的空壳计划**不算完成**。
- **痕迹位**：同 §0 第 2 环。
- **可重入**：已有计划则**只补缺段**，不重写、不重排编号；取证不足只补取证。
- **降级**：无 sub-agent 能力时内联调研，并**明确声明这是单遍内联取证**（与 §5 质量轮降级同规则）。

### 第 3 环 · 审阅计划

> 七环里**唯一没有现成 skill** 的语义环——执行前挑出计划的漏洞，比执行后返工便宜一个数量级。

- **目的**：在执行前把计划的漏洞挑出来。
- **进入证据**：同 §0 第 3 环（计划**重大修订后需重审**）。
- **动作**（**默认轻量**）：**主 agent 自审**，按三轴逐条给结论——不派 sub-agent（省固定成本）；仅当**改动面大／不可逆点多／声明段要求**时，才派独立 sub-agent 重审。
  1. **完整性**——骨架齐否？验收**可判定**否（是"能跑通／0 警告"还是"做好了"）？依赖与前置列出否？
  2. **事实**——**取证是否充分**（`file:line`、命令、一手链接），而非事后再补断言？
  3. **风险**——不可逆点、回滚路径、权限边界、安全与凭据。
- **退出判据**：每条发现给出「**已修订**」或「**需拍板（带推荐）**」；**必须留痕**。
- **痕迹位**：同 §0 第 3 环（重审覆盖同一位置，注明日期）。
- **可重入**：重审只更新结论，不删除既有审阅记录。
- **托管**：发现属 §5 ②档（口径／不可逆）→ 记入计划 `## 托管阻塞点`。

### 第 4 环 · 执行

- **目的**：按计划把改动做完，并保持文档与设计闭环。
- **进入证据**：同 §0 第 4 环（部分完成 ⇒ **只做剩余**）。
- **动作**（纪律）：
  - **计划驱动**：动作不超出计划范围；超范围先回第 2 环补计划（小超范围可在执行记录留痕）。
  - **一次一功能、垂直切片**（项目可加严）。
  - **只跑相关测试**，不跑全量（全量留给收尾或 CI）。
  - **文档与设计闭环**：改代码**必须**同步声明指定的落点，不留"代码改了、文档没跟"。
  - **自动判断提交时机**：一逻辑切片一提交，不必每次询问；提交纪律见 §6。
  - **常规自动修，非常规停下**：业务口径／不可逆／影响面大／只该由人拍板的 ⇒ 转第 1 环（托管模式见 §5）。
  - **TDD 是可选风味**：声明段 `TDD 风味: 开` 或用户指定时，以 `tdd` 纪律执行（先红后绿）；默认不强制。
- **退出判据**：进度表全绿 ＋ 验证段命令通过。
- **痕迹位**：同 §0 第 4 环。
- **可重入**：按进度表跳过已完成模块，不重做已绿模块。

### 第 5 环 · 简化轮

- **目的**：把"能跑"的改动清干净——去重、拆复杂、砍浪费、把创可贴换成深修。
- **进入证据**：同 §0 第 5 环。
- **动作**：委派 `simplify-code`。两点务必利用：
  - **审查轴可被改写**（例：`目标是**找漏洞和优化，不是精简**`）——改写后按项目给定轴审，而非默认四轴；
  - **对象可以是文档／计划**，不限于 diff 代码。
- **委派**：**恒派独立 sub-agent**（不污染主上下文）——委派方式不是项目开关。无 sub-agent 能力时降级内联各轴，并**明确声明这是单遍内联审阅**。
- **退出判据**：报告分「**已自动修**」与「**需拍板（带推荐）**」；落修后跑相关测试；跳过项写明理由。
- **痕迹位**：同 §0 第 5 环。
- **可重入**：无记录即视为未做。

### 第 6 环 · 审查轮

- **目的**：双轴复核——**Standards**（是否符合本项目成文规范）与 **Spec**（是否忠实实现原始诉求）。
- **进入证据**：同 §0 第 6 环。
- **动作**：委派 `code-review`；**固定基准点**取声明段 `审查基准`（未声明则由本次调用给出）。
- **委派**：**恒派独立 sub-agent**（两轴各自独立，**不得互相遮蔽**）——委派方式不是项目开关；无 sub-agent 能力时按第 5 环同规则降级内联并声明。
- **退出判据**：两轴报告 ＋ 处理结论（哪些改了、哪些不改及理由）；报告落 `报告落点`（若声明有）。
- **痕迹位**：同 §0 第 6 环。
- **可重入**：无记录即视为未做。

### 第 7 环 · 收尾

- **目的**：把这次任务的**所有**后果落到它该落的地方，不留悬空。
- **进入证据**：同 §0 第 7 环。
- **动作**：跑 §6 收尾清单。
- **退出判据**：§6 六项全办齐（**托管模式下另加一次记录回填**）。
- **痕迹位**：同 §0 第 7 环。
- **可重入**：缺哪项补哪项。

## §3 外层循环：多计划

- **一次只跑一个计划**：计划是外层循环的单位，**执行必须串行**（同一工作区）。多计划可并行**存在**，不可并行**执行**。
- **顺序＝依赖顺序**：用计划头 `> 前序:`（若项目索引另含依赖列，也可用）；无依赖声明时**按编号**。
- **结果带入下一计划**：上一计划的产出写进下一计划头部 `> 前序: <编号>（产出…）`；影响协作的决策另起台账条目。下一计划的**第 3 环审阅**须据此核对一致性。
- **计划间必须清理上下文**（§4）——**严禁**不清理就开下一个计划。

## §4 上下文卫生（计划之间）

**先判 handoff，再选 compact／new**：

| 判据 | 动作 |
|---|---|
| 换 harness／换目录／移交他人／内容只对新窗口有用 | 调 `handoff` skill（见下方"不可自调"说明），再看下一行 |
| **有依赖证据**：`> 前序:` 指向、共享文件、共享域、共享未决项 | `/compact`（压缩但保留推理链） |
| **弱关联**：跨域／跨仓／无引用证据 | `/new`（Claude Code：`/clear`）——**默认倾向** |

- **`handoff` 可能不可自调**：本机 `handoff` skill 带 `disable-model-invocation`（与 `implement` 同理），模型**不得自动调用**。托管或无法自调时：**降级为 `/new` ＋ 在计划「执行记录」写明「应交未交：<交接内容摘要>」**，不阻塞流水线。
- 判定由 agent 自决，但**必须打印**：`上下文：选 <compact|new>（handoff: 是/否），原因 <理由>`。
- **拿不出依赖证据就倾向 `/new`**——目的正是防上下文污染与自动压缩打爆。
- 交互模式不停下等确认；托管模式无人确认即执行。
- **与 `ask-matt/PHASE-BOUNDARIES` 的分工**：那套判据面向"会话内阶段边界"（含 Continue／subagent 两种本 skill 不覆盖的选项，且把 `/compact` 当默认）；本 skill 面向**计划之间的交接**，默认倒向 `/new`。两者结论不同是**场景不同**，不是冲突——计划间以本 skill 为准。

## §5 托管模式（无人值守）

### 开关（优先级从高到低）

1. **触发词**（本次有效）：说「托管跑／无人值守／全权托管」进入；说「停止托管」退出。
2. **标记文件**（持久）：`.agent/pipeline/autonomy` 存在即托管——重启、新会话、换 agent 仍在。
3. **项目默认**：声明段 `托管默认: 开/关`。

### 接管边界（三档）

| 档 | 范围 | 无人时行为 |
|---|---|---|
| **① 可逆 & 影响小** | 命名、局部重构、补测试、文档措辞、排序、索引同步 | **自决执行**，逐条记入计划 `## 托管决策记录`，标 `待复核` |
| **② 不可逆／影响面大／业务口径** | 删数据、改库结构、改对外口径、删文件、改公共契约、**推送／发布**、需人凭据的操作 | **不做**：该步阻塞、其余照走；计划状态标「部分完成（托管阻塞）」；待拍板点＋推荐列 `## 托管阻塞点` |
| **③ 项目红线** | 声明段 `红线:` 列出的（例：环境库只读禁写） | **永远不做**——**托管不解除红线** |

### 决策记录契约

- **计划内为主**：`## 托管决策记录`（列：时间｜决策｜理由｜影响面｜可回滚性｜复核状态）＋ `## 托管阻塞点`。
- **台账仅在跨协作时另立**：影响后续协作／跨计划的①档决策，才另起决策台账条目，并在记录里标 `已落 <编号>`——不造第二真源。
- **人回来的第一件事**：读这两节 → 逐条复核／裁决 → 把 `待复核` 改为结论。

## §6 收尾清单

1. **计划状态回填**：计划头状态 ＋ 进度表；**索引状态同步**（翻绿）。
2. **托管记录回填**（托管模式下必办）：`## 托管决策记录`／`## 托管阻塞点` 已写完，状态为 `待复核`／`待裁决`——**否则人回来没有复核入口**。
3. **时间线**：声明指定了时间线文件时，追加**一行**（何时 · 做了什么 · 落在哪）。
4. **文档闭环**：声明指定的所有落点（决策台账／设计稿／环境事实／README 等）**全部**同步。
5. **门禁**：声明给出的命令全绿（构建／测试／文档）。
6. **提交**：提交信息交 `commit-message` skill；**精确 pathspec**（`git commit --only <path>`）——**禁裸 `git commit`**、**禁裸 `git add -A`**；**回退／重置前先 `git log` 核对**（共享分支上 `HEAD~1` ≠「你上一个提交」）。本仓另有约定时以声明段为准。
7. **不越权**：**推送、发布、破坏性操作不在收尾内**——属 §5 ②档，需人执行或显式授权。

---

## §7 项目声明

项目在其 `AGENTS.md`（或等价指令文件）写一段 `## 工作流水线`。

- **字段定义的真源是 `TEMPLATE.md`**（不是本节）；本 skill 启动时读它，没有声明则走最小默认。
- **声明字段集合 ＝ 接口版本**：增删字段属接口变更，必须在 Release 说明中标注，并同步 `TEMPLATE.md`。

> **能力名优先、命令名其次**：某 agent 没有同名命令时，**按能力找它的等价物**，不要因命令缺失而跳过该环。带 `disable-model-invocation` 的 skill（如 `handoff`）需按 §4 的降级规则处理。

## 硬性禁止

- ❌ 不判位置就从头重跑（浪费，且可能覆盖他人已完成的工作）
- ❌ 计划间不清理上下文就开下一个计划（§4）
- ❌ 托管模式下执行②／③档操作（§5）
- ❌ 收尾漏项（§6 七项）
- ❌ 复制被委派 skill 的正文（见「定位与边界」）
- ❌ 把任何具体项目的落点、命令、台账名硬编码进本 skill（见「定位与边界」）
