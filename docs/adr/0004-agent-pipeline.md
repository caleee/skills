# ADR-0004: 跨 agent 工作流水线 Skill（agent-pipeline）

- 状态：已接受（grilling 10 轮收束）
- 日期：2026-09-29
- 前序：ADR-0001（版本与发布策略）、ADR-0002（plan-persist）、ADR-0003（根 agent 指令文件更名）

## 背景

`tenant` 仓（多 agent 长期协作交付）已沉淀一条经验证的工作流水线，写在它的根 `AGENTS.md` 工作流水线段落：

> `/grill-me` → 计划 → 审阅计划 → 执行 → `/simplify` → `/code-review` → 收尾

该流水线的**骨架是通用的**，但正文与项目落点深度耦合——决策落 `docs/raw/decisions.md`、范围落 `plans/<域>/index.md`、机制落 `design/`、时间线落 `agent-task-log.md`、操作一律走 `tools/tz`。换一个项目即不可用；且没有跨 agent 的载体（cc 的 slash 写法与 pi 的 skill 名靠项目表手工映射）。

**现有 skill 盘点**（扫描根 `~/.agents/skills`，撰写时该目录 42 个 skill；逐条核对 `name`／`description`）显示七环的覆盖是**残缺的**：

| 环 | 现成 skill | 结论 |
|---|---|---|
| 追问对齐 | `grilling`／`grill-me`／`grill-with-docs` | ✅ 有 |
| 计划落盘 | `plan-persist` | ✅ 有 |
| **审阅计划** | 无（`code-review` 的基准是 diff＋spec，`simplify-code` 只是"目标可改写"） | ❌ 缺口 |
| **执行** | `implement`（`disable-model-invocation: true`、TDD 口味、假定 issue tracker） | ⚠️ 不匹配 |
| 简化轮 | `simplify-code` | ✅ 有 |
| 审查轮 | `code-review` | ✅ 有 |
| 提交 | `commit-message` | ✅ 有 |
| **编排／闸门／收尾** | 无 | ❌ 缺口 |
| **中途接入／多计划串行／上下文卫生／无人值守** | 无直接对应（`handoff` 只覆盖"留交接文档"、`ask-matt/PHASE-BOUNDARIES` 覆盖"会话内阶段边界"、`wayfinder` 覆盖"跨会话大计划决策"——均不复用本语义） | ❌ 缺口 |

**目标一句话**：把「通用骨架」从「项目落点」剥出来，交付跨 agent、跨项目的 `agent-pipeline`——**skill 给判据，项目给命令与落点**。

## 决策

> 下列 10 条与本 skill 落盘计划 `.agent/plans/04-agent-pipeline-skill.md` 的「十轮决策」一一对应；第 4 条另含用户在轮次间追加的硬要求。

### 1. 定位：编排器 ＋ 项目声明制（最小默认兜底）

七环**点名**既有 skill 执行（`grilling`／`plan-persist`／`simplify-code`／`code-review`／`commit-message`），不复制其正文；本 skill 只承载**编排、闸门、降级、接入、外层循环、托管、收尾**这七件没有归属的事。

通用性来自「**读取声明**」而非「内置假设」：项目在 `AGENTS.md` 写一段 `## 工作流水线` 声明其落点／命令／红线／托管默认（模板见 `agent-pipeline/TEMPLATE.md`）；无声明时走最小默认（`.agent/plans/` ＋ 无外部台账 ＋ 空门禁）。

### 2. 单 skill，不拆

审阅计划、执行纪律、收尾清单**内联**在 `SKILL.md`。顺序与闸门是同一件事，拆开即废；且多一个 skill 就多一条发布线、一份索引项、一层跨 skill 契约。`plan-review` 留作未来抽离——届时按**零返工**搬运（执行环的纪律与审阅环的 brief 均按自包含写法撰写）。

### 3. 执行环：内联纪律，`implement`/`tdd` 降为可选风味

`implement` 的 `disable-model-invocation: true` 会**掐断自动推进**（与"自行判断环节、不停下等人点头"直接冲突），且 TDD 口味与 issue-tracker 输入假定不合；其 `tdd` 纪律作为**项目声明可开启的可选风味**（`TDD 风味: 开`）保留。执行环内联纪律＝计划驱动 ＋ 一次一功能垂直切片 ＋ 只跑相关测试 ＋ 文档闭环 ＋ 自动判断提交时机 ＋ 常规自动修。

### 4. 外层循环与上下文卫生（含用户追加要求）

- **多计划串行**：一次只跑一个计划（执行串行）；顺序＝依赖顺序（计划头 `> 前序:`），无声明按编号；上一计划产出写入下一计划头部，**带入下一计划的审阅环**核对。
- **上下文卫生**：**先判 `handoff`，再选 `compact`/`new`**——有依赖证据（`> 前序:` 指向、共享文件、共享域、共享未决项）→ `/compact`；弱关联 → `/new`（cc `/clear`）。**拿不出依赖证据就倾向 `/new`**（防上下文污染与自动压缩打爆）。必须打印选择与理由。计划间**严禁不清理上下文就开下一个**。
- **`handoff` 的降级**：本机 `handoff` skill 带 `disable-model-invocation`，模型不得自动调用；托管或不可自调时降级为 `/new` ＋ 在执行记录写明「应交未交」摘要，**不阻塞流水线**（与决策 3 同一条理由，此处一并适用）。
- 与 `ask-matt/PHASE-BOUNDARIES` 的分工：那套面向"会话内阶段边界"（含 Continue／subagent 两种本 skill 不覆盖的选项，且以 `/compact` 为默认）；本 skill 面向"计划之间的交接"，默认倒向 `/new`。场景不同，故结论不同——**计划间以本 skill 为准**。

### 5. 托管（无人值守）三档边界

- **① 可逆 & 影响小** → 自决执行 ＋ 逐条记入计划 `## 托管决策记录`（标 `待复核`）
- **② 不可逆／影响面大／业务口径**（含**推送与发布**）→ **不做**：阻塞单点、不阻塞整盘；计划状态标「部分完成（托管阻塞）」；待拍板点 ＋ 推荐列 `## 托管阻塞点`
- **③ 项目红线** → **永远不做**，托管不解除

### 6. 托管开关三层

触发词（本次）> `.agent/pipeline/autonomy` 标记文件（持久）> 项目声明 `托管默认`。三个入口都不依赖任何 agent 的特有机制（纯约定 ＋ 文件），故跨 agent 行为一致。

### 7. 接入判定：位置探针表 ＋ 位置报告 ＋ 不确定退更早环

为七环各定义**痕迹位**（可机械验证），从后往前探，最先"未完成"者即当前环；证据不足／矛盾时**退到能确证的最早环**（安全侧：宁重跑审阅，不漏环）；各环**可重入**；判定后**不停下等确认**（否则与托管互斥）。痕迹位**优先取声明指定位置**，推荐约定为计划头 `> 已裁决:` / `> 审阅:` 两个字段，项目未采用时退回「计划正文中有对应记录」。

### 8. 真源归属：skill 承载全文与映射

skill 是流水线正文与跨 agent 能力映射的**单一真源**（因此可独立安装——单装 skill 的人才知道某环在本 agent 叫什么）；全局 `~/.agents/AGENTS.md` 只保留 grilling 口径、`ok` 约定这类**元约定**（可瘦身为一行路由）；项目 `AGENTS.md` **只写声明段**，不复制正文。

> **后续（2026-09-29，`MT-147`，skill 优先）**：本决议「全局保留 grilling 口径」**收紧为路由**——全局 §1 Grilling 的 5 条细则已退化为一行路由（判据归 `grilling` skill）；`ok` 约定属元约定，仍留全局。

### 9. Gate 形态：判据来自 skill，命令来自项目

不引入 `.agent/pipeline.yaml` 之类机器可读配置（`.agent/` 是 gitignore 的本地便笺，放跨机器通用配置自相矛盾），不内置探针脚本（项目落点高度异构，脚本只能假设一套默认）。载体用 **`AGENTS.md`**——各 agent 都已会读的唯一公共载体；项目已提供检查命令时，agent 直接调用以获得机械判定。

### 10. 交付形态

`agent-pipeline.md`（根，单行 `description`）＋ `agent-pipeline/{SKILL.md, AGENT.md, TEMPLATE.md, VERSION=0.1.0}`。**`TEMPLATE.md` 独立成文件**：声明段是 skill 与项目之间的**接口**，接口应有自己的文件（可整段复制、可稳定引用）；`AGENT.md`（**单数**，沿 `ADR-0003` 对 skill 包内命名的决定）承载运行指引。`TEMPLATE.md` 是**声明字段定义的真源**，字段集合即接口版本。

## 备选与否决

| 备选 | 否决理由 |
|---|---|
| skill 内置一套通用落点默认 | 与既有项目惯例冲突，制造**第二真源**（正是"信息差＝协作事故"最忌） |
| 纯序列、不管落点与闭环 | 丢掉流水线中最有价值的闭环 ＋ 台账 ＋ 收尾，退化为流程图摆设 |
| 拆 `plan-review` / `closeout` 为独立 skill | 拆散"顺序 ＋ 闸门 ＋ 不可漏的收尾"这一立身之本；多两条发布线与跨 skill 契约 |
| 执行环委派 `implement` | `disable-model-invocation` 掐断自动推进；TDD/tracker 口味不合 |
| 托管全自决 | 无人复核下做不可逆决策（删库、改契约、推送），风险不可接受 |
| 托管全阻塞 | 一次小决策即挂起整个计划，托管退化为低效模式 |
| 计划间一律 `handoff` ＋ 新窗 | `handoff` 落系统临时目录、非长期资产，面向"换人/换环境"而非"同人连跑"；且其 `disable-model-invocation` 使无人值守下不可自调 |
| 全局 `~/.agents/AGENTS.md` 承载流水线正文 | 破坏 skill **可独立安装**契约（单装 skill 者拿不到全局约定）；且全局指令应保持"元约定"定位 |
| 流水线正文复制进每个项目 | N 份副本、改一次改 N 处 |
| 引入 `.agent/pipeline.yaml` | 引入第二个真源 ＋ schema；且 `.agent/` 不入仓，跨机器即丢 |
| skill 内置探针脚本 | 落点异构现实下只能假设一套默认（多数项目不符）或参数化到无人愿用；与 `plan-persist` 已确立的"轻量、不带脚本"取向相左 |
| 声明模板内联进 `SKILL.md`（无独立文件） | **ADR-0002 决策 6 曾定「不加独立模板文件」，此为有意偏离**：那条针对"没有外部接口"的 `plan-persist`；本 skill 的声明段是**跨项目接口**，接口需要稳定锚点（可整段复制、可单独演进） |
| 把 tenant 声明段作为示例文件入 skill | 项目专有内容进通用 skill，后来者易误读为"默认就该这么写" |

## 后果

- **`agent-pipeline` 成为流水线正文的单一真源**；`~/.agents/AGENTS.md` 保留 grilling 口径与 `ok` 约定等元约定，不再承载流程正文。**（2026-09-29 起亦不承载 grilling 细则，见 §8 后续注记；`MT-147`）**
- **tenant 的 `AGENTS.md` 工作流水线段落**应在后续任务中改造为**声明段**（跨仓改动，见 `.agent/plans/04` 的 `## 托管阻塞点` **B1/B2**，待用户裁决）——改造前两处并存不冲突（tenant 那份写得更细，本 skill 更通用）。
  > **后续（2026-09-29，`MT-146`）**：**已落地**——tenant `AGENTS.md` 改造为 15 字段声明段（`73c0e29d`）；全局 `~/.agents/AGENTS.md` 新增「工作流水线（路由）」节（`07071b0`／质量轮落修 `1d3987f`）。**B2 关闭**；B1（push ＋ Release）待用户。
- **痕迹位成为接入能力的硬前提**：项目的计划模板需保留七环对应位置（见 `AGENT.md` §痕迹位），否则接入判定会持续退到更早环。位置缺失时探针会退回"正文中有记录"，但可靠性下降。
- **`plan-review` 的抽离口**被显式保留：执行环与审阅环按自包含写法撰写，未来抽离为零返工搬运。
- 与 `plan-persist` 形成**分层**：前者管执行期载体（"这个计划做到哪了"），后者管编排与闸门（"整件事走到哪一步了、下一步该谁"）。
- **声明字段集合即接口版本**：增删字段须同步 `TEMPLATE.md` 并在 Release 说明标注。
- 发布仍走 `release-skill.yml`（`VERSION` bump → tag `agent-pipeline-v<ver>` → `git archive` zip → Release），无需改 workflow。
